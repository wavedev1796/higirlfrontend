# HG-F3-015 - Auditoria UX/UI Fase 3: Tipografía, Breakpoints, Iconos y Transiciones


## Resumen

Tercera y última fase de la auditoría UX/UI. Se migró la fuente de headings a
Poppins según las guías oficiales de marca, se normalizó el sistema de breakpoints,
se implementó sidebar colapsable en tablet, se unificó el sistema de iconos con
Lucide React, y se activaron transiciones de página mediante la View Transitions
API de React 19.

---

## Objetivo

- Alinear tipografía de headings con la guía de marca oficial (Poppins, no League Spartan).
- Normalizar breakpoints ad-hoc a una escala sistemática de cuatro puntos.
- Sidebar colapsable en tablet mediante clase CSS + estado local.
- Reemplazar `FieldIcon` personalizado con iconos Lucide (consistencia de estilo).
- Transiciones de página suaves entre rutas del dashboard.
- Modo oscuro: diferido a decisión del equipo.

---

### P1 - Tipografía: League Spartan → Poppins

**Motivación:** La guía de marca oficial de Hi Girl especifica Poppins como fuente
de headings. League Spartan fue una elección inicial incorrecta.
Lora (fuente de cuerpo) se confirmó como correcta — no se migró.

**Archivos modificados:**

```text
src/app/layout.tsx
src/styles/tokens.css
src/styles/base.css
src/styles/layouts.css
```

**Cambios clave:**

```ts
// layout.tsx — antes
import { League_Spartan } from "next/font/google";
const spartan = League_Spartan({ variable: "--font-spartan", ... });

// layout.tsx — después
import { Poppins } from "next/font/google";
const poppins = Poppins({
  variable: "--font-poppins",
  subsets: ["latin"],
  weight: ["400", "500", "600", "700"],
  display: "swap",
});
```

```css
/* tokens.css */
--font-heading: var(--font-poppins); /* era var(--font-spartan) */

/* base.css — fallback stack actualizado */
font-family: var(--font-poppins), "Poppins", Arial, Helvetica, sans-serif;
```

Todos los usos de `var(--font-spartan)` en `layouts.css` (6 ocurrencias)
reemplazados con `var(--font-poppins)`.

### P2 - Breakpoints normalizados

**Motivación:** El código tenía breakpoints ad-hoc (620, 640, 767, 860, 900, 1140 px)
sin coherencia entre archivos.

**Escala oficial adoptada:**

| Punto | Valor | Uso |
|---|---|---|
| Mobile | 480px | Stack de formularios, field-grid |
| Tablet pequeña | 768px | Profile grid, skeleton grid |
| Tablet / laptop | 1024px | Sidebar colapsable, layout principal |
| Desktop | 1280px | Columnas del dashboard en ancho máximo |

**Mapeo de migración:**

| Antes | Después | Archivo |
|---|---|---|
| `max-width: 620px` | `480px` | `layouts.css` |
| `max-width: 640px` | `480px` | `components.css` |
| `max-width: 860px` | `1024px` | `layouts.css` (sidebar — tablet concern) |
| `max-width: 900px` | `768px` | `layouts.css` (profile-grid — tablet concern) |
| `max-width: 1140px` | `1280px` | `layouts.css` (dashboard columns) |

### P3 - Sidebar colapsable en tablet

**Archivos modificados:**

```text
src/styles/layouts.css
src/app/(dashboard)/feed/page.tsx
```

**Patrón implementado:**

- Clase `.sidebar-open` en `.dashboard-container` controla visibilidad.
- En `@media (max-width: 1024px)` el sidebar está oculto por defecto.
- Al hacer click en `.sidebar-toggle`, se alterna `sidebarOpen` en estado local.
- Botón con `aria-expanded` y `aria-controls="community-sidebar"` para accesibilidad.

```tsx
// feed/page.tsx
const [sidebarOpen, setSidebarOpen] = useState(false);

<div className={`dashboard-container${sidebarOpen ? " sidebar-open" : ""}`}>
  <aside id="community-sidebar" className="dashboard-sidebar">...</aside>
  <main className="dashboard-feed">
    <button
      type="button"
      className="sidebar-toggle"
      onClick={() => setSidebarOpen((p) => !p)}
      aria-expanded={sidebarOpen}
      aria-controls="community-sidebar"
    >
      <Users size={15} aria-hidden />
      {sidebarOpen ? "Ocultar comunidad" : "Ver comunidad"}
    </button>
    ...
  </main>
</div>
```

```css
/* layouts.css */
.sidebar-toggle { display: none; }

@media (max-width: 1024px) {
  .dashboard-sidebar { display: none; }
  .dashboard-container.sidebar-open .dashboard-sidebar {
    display: block;
    width: 100%;
  }
  .sidebar-toggle {
    display: inline-flex;
    /* estilos de marca: brand-strong, radius-sm */
  }
  .sidebar-toggle[aria-expanded="true"] { /* estado activo */ }
}
```

### P4 - Sistema de iconos Lucide unificado

**Motivación:** El proyecto tenía `FieldIcon.tsx` (SVG inline customizado) que
no seguía ningún sistema consistente. Se migró a Lucide React para tener
un único icon set con stroke width y corner radius uniformes.

**Archivos modificados:**

```text
src/features/auth/components/RegisterForm.tsx   — iconos de campo
src/shared/components/ui/Button.tsx             — spinner de carga
src/app/(dashboard)/feed/page.tsx               — icono sidebar toggle
```

**Archivo eliminado:**

```text
src/shared/components/icons/FieldIcon.tsx       — ELIMINADO (sin importers restantes)
```

**Iconos migrados en RegisterForm:**

| Antes (`FieldIcon name`) | Después (Lucide) |
|---|---|
| `"user"` | `<User size={18} aria-hidden />` |
| `"mail"` | `<Mail size={18} aria-hidden />` |
| `"lock"` | `<Lock size={18} aria-hidden />` |
| `"eye"` / `"eye-off"` | `<Eye>` / `<EyeOff>` (toggle dinámico) |
| `"calendar"` | `<Calendar size={18} aria-hidden />` |
| `"map-pin"` | `<MapPin size={18} aria-hidden />` |

**Spinner en Button.tsx:**

### P5 - Transiciones de página (View Transitions API)

**Motivación:** React 19 + Next.js 16 soportan la View Transitions API de forma
nativa. Permite transiciones suaves entre rutas sin librerías externas.

**Archivos modificados:**

```text
next.config.ts
src/styles/base.css
src/app/(dashboard)/layout.tsx
```

**Configuración:**

```ts
// next.config.ts
const nextConfig: NextConfig = {
  experimental: { viewTransition: true },
};
```

**CSS de transiciones:**

```css
/* base.css */

/* Header anclado — no anima durante transiciones de página */
::view-transition-group(dashboard-header) { animation: none; z-index: var(--z-header); }
::view-transition-old(dashboard-header)   { display: none; }
::view-transition-new(dashboard-header)   { animation: none; }

/* Contenido: fade-out rápido + fade-in con slide suave */
::view-transition-old(.page-enter) {
  animation: 150ms cubic-bezier(0.4, 0, 1, 1) both vt-page-out;
}
::view-transition-new(.page-enter) {
  animation: 250ms cubic-bezier(0, 0, 0.2, 1) 150ms both vt-page-in;
}

@keyframes vt-page-out { to { opacity: 0; } }
@keyframes vt-page-in  { from { opacity: 0; transform: translateY(0.4rem); } }

/* Desactivar para prefers-reduced-motion */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(*), ::view-transition-new(*), ::view-transition-group(*) {
    animation-duration: 0s !important;
    animation-delay:    0s !important;
  }
}
```

**Layout del dashboard:**

```tsx
// src/app/(dashboard)/layout.tsx
import { ViewTransition } from "react";

<header style={{ viewTransitionName: "dashboard-header" }}>
  ...
</header>

<main className="dashboard-main">
  <ViewTransition enter="page-enter" default="none">
    {children}
  </ViewTransition>
</main>
```

### P6 - Modo oscuro (DIFERIDO)

Decisión tomada por el equipo: el modo oscuro requiere definir una paleta
alternativa completa alineada a la guía de marca. Se discutirá en sprint
posterior. No se implementó ningún cambio relacionado.

### P7 - Feed: decisión de arquitectura

Se intentó un rediseño del feed con tarjetas de recomendaciones en tiempo real.
**Revertido** por decisión del producto: el área de feed está reservada para
un futuro módulo de foros/publicaciones. Mostrar usuarios en el feed duplicaría
la funcionalidad de la pestaña Descubrir.

Estado final del feed: empty state "Última actividad" con CTA a `/descubrir`.

## Criterios de aceptacion

- [x] Headings usan Poppins en todos los componentes.
- [x] Lora permanece como fuente de cuerpo.
- [x] Sin referencias a `League Spartan` o `--font-spartan` en el codebase.
- [x] Breakpoints siguen escala 480 / 768 / 1024 / 1280 px.
- [x] Sidebar se colapsa en pantallas ≤ 1024px con toggle accesible.
- [x] `FieldIcon.tsx` eliminado; todos los iconos son Lucide.
- [x] Transiciones de página activas en el dashboard.
- [x] Header no parpadea durante las transiciones.
- [x] `prefers-reduced-motion` desactiva todas las transiciones.
- [x] Feed muestra empty state — sin datos de usuarios ni recomendaciones.
