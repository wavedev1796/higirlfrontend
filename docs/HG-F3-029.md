# HG-F3-029 - Quitar Tailwind y eliminar la capa muerta de interceptores

## Resumen

Dos hallazgos de la auditoría ponytail del frontend
(`docs/ponytail/2026-08-05-higirlfrontend.md`): se elimina la dependencia de
Tailwind, que se cargaba entera para cinco clases utilitarias en un solo
archivo, y se borra `infrastructure/api/interceptors.ts`, código muerto que
además contenía una implementación peor que la vigente.

## Objetivo

Que el proyecto deje de arrastrar una dependencia que sus propias reglas
prohíben, y que no queden dos implementaciones del mismo helper con una de
ellas rota.

## 1. Tailwind eliminado

### Situación

`src/styles/tokens.css` hacía `@import "tailwindcss"`, había un
`postcss.config.mjs` cuyo único contenido era el plugin de Tailwind, y dos
devDependencies (`tailwindcss`, `@tailwindcss/postcss`).

El uso real era **cinco clases utilitarias en un archivo**:

```tsx
// app/layout.tsx — antes
<html className={`${poppins.variable} h-full antialiased`}>
  <body className="min-h-full flex flex-col">
```

Ningún otro componente usaba utilidades de Tailwind. `AGENTS.md` y `CLAUDE.md`
además establecen: *"CSS: Vanilla CSS organizado en `styles/` — NO usar
Tailwind"*.

### Cambio

Las cinco utilidades pasan a `base.css`, sobre los selectores que ya existían:

```css
html {
  height: 100%;          /* h-full */
  scroll-behavior: smooth;
}

body {
  display: flex;         /* flex */
  min-height: 100%;      /* min-h-full */
  flex-direction: column;/* flex-col */
  /* -webkit-font-smoothing: antialiased ya estaba */
}
```

`layout.tsx` queda sin clases utilitarias: el `<html>` conserva solo la variable
de la fuente y el `<body>` ya no lleva `className`.

Se elimina `postcss.config.mjs`. La documentación de Next 16
(`01-getting-started/11-css.md`) confirma que ese archivo existe únicamente para
registrar el plugin de Tailwind; sin Tailwind no cumple ninguna función.

### Verificación

No basta con que compile: se sustituyó CSS estructural (`display: flex` en el
`body`). Se compararon los estilos computados en el navegador después del
cambio:

| Propiedad | Esperado (lo que daba Tailwind) | Obtenido |
|-----------|--------------------------------|----------|
| `html.height` | 100% del viewport (720px) | `720px` ✅ |
| `body.display` | `flex` | `flex` ✅ |
| `body.flexDirection` | `column` | `column` ✅ |
| `body.minHeight` | `100%` | `100%` ✅ |
| `body.webkitFontSmoothing` | `antialiased` | `antialiased` ✅ |

`document.body.className` quedó vacío y `/login` renderiza completo, sin errores
de consola.

## 2. `interceptors.ts` eliminado

`src/infrastructure/api/interceptors.ts` (38 líneas) exportaba `buildHeaders()`
y `getResponseMessage()`. **Ningún archivo lo importaba.** `lib/api.ts` tiene sus
propias versiones de ambas y son las que están en uso.

No era solo código muerto: el `buildHeaders` del interceptor fijaba siempre
`Content-Type: application/json`, mientras que el de `lib/api.ts` lo omite
cuando el cuerpo es `FormData`. Reconectar el archivo muerto —creyendo que era
el canónico— **habría roto la subida de fotos de perfil**.

## Archivos Modificados

```text
src/styles/tokens.css                    (quita @import "tailwindcss")
src/styles/base.css                      (html/body con las reglas equivalentes)
src/app/layout.tsx                       (sin clases utilitarias)
postcss.config.mjs                       ELIMINADO
src/infrastructure/api/interceptors.ts   ELIMINADO
package.json                             (-tailwindcss, -@tailwindcss/postcss)
package-lock.json                        (regenerado)
```

## Criterios de Aceptación

- [x] No queda ninguna referencia a Tailwind en `src/` ni en los archivos de configuración.
- [x] `tailwindcss` y `@tailwindcss/postcss` fuera de `package.json` y de `node_modules`.
- [x] El layout raíz mantiene los mismos estilos computados que con Tailwind.
- [x] `/login` renderiza completo y sin errores de consola.
- [x] `interceptors.ts` eliminado y sin referencias.
- [x] Lint y build sin errores.

- Build de Next.js generado correctamente.
- Verificación adicional en navegador: estilos computados de `html`/`body`
  idénticos a los que producía Tailwind.
