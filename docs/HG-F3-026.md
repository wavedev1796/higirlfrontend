# HG-F3-026 - Fix del reset de contrasena y reenvio del correo de activacion

## Resumen

Dos cambios en el flujo de autenticacion: se corrigio el formulario de nueva
contrasena, que fallaba siempre, y se agrego un boton para reenviar el correo de
activacion cuando el login rechaza una cuenta sin verificar.

## Objetivo

Que restablecer la contrasena funcione desde la interfaz, y que una usuaria cuya
cuenta quedo sin activar pueda desbloquearse sola en vez de quedar atrapada.

## Causa raiz del reset roto

`auth.service.ts` enviaba el cuerpo `{ password, token }`, pero el DTO del
backend (`ResetPasswordDto`) espera `newPassword`. Como el backend aplica un
`ValidationPipe` global con `forbidNonWhitelisted: true`, la peticion se
rechazaba dos veces: por propiedad desconocida (`password`) y por campo
requerido ausente (`newPassword`).

Respuesta real del backend antes del arreglo:

```json
{"message":["property password should not exist",
            "La nueva contrasena es requerida",
            "newPassword must be a string"],
 "statusCode":400}
```

El formulario nunca funciono: cualquier intento de restablecer la contrasena
devolvia 400. No se habia detectado porque las pruebas del endpoint se hacian
por API con el nombre de campo correcto.

## Alcance Implementado

- **`auth.service.ts` → `resetPassword`:** envia `newPassword` en lugar de
  `password`. Queda un comentario indicando por que el nombre importa.
- **`endpoints.ts`:** nueva entrada `AUTH.RESEND_VERIFICATION`.
- **`auth.service.ts` → `resendVerification(email)`:** llamada al endpoint nuevo
  `POST /auth/resend-verification`.
- **`LoginForm.tsx`:** cuando el error del login corresponde a una cuenta sin
  verificar, el mensaje muestra un boton "Reenviar correo de activacion". Tras
  pulsarlo se reemplaza por un texto neutral, porque el backend responde lo
  mismo exista o no la cuenta (no revela que emails estan registrados). El boton
  se deshabilita si el campo de correo esta vacio.
- **`components.css`:** clase `.link-button` para acciones inline dentro de un
  mensaje de estado.

## Archivos Modificados

```text
src/features/auth/services/auth.service.ts     (fix del payload + resendVerification)
src/features/auth/components/LoginForm.tsx     (boton de reenvio)
src/infrastructure/api/endpoints.ts            (RESEND_VERIFICATION)
src/styles/components.css                      (.link-button)
```

## Criterios de Aceptacion

- [x] Restablecer la contrasena desde `/reset-password` funciona y ya no da 400.
- [x] El boton de reenvio aparece solo ante el error de cuenta sin verificar.
- [x] El boton no aparece con otros errores de login (credenciales incorrectas).
- [x] Tras reenviar, el mensaje no revela si la cuenta existe.
- [x] El resto de payloads del frontend fue auditado contra los DTOs del backend
      y ninguno mas presenta discrepancias.
