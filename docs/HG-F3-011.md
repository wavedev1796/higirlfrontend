# HG-F3-011 - Indicador de compatibilidad y detalle de afinidad

## Resumen

Se implemento en el frontend el indicador de porcentaje compatible para las
tarjetas de perfiles recomendados y una pantalla de detalle de afinidad. El
porcentaje mostrado proviene directamente del backend, desde el endpoint de
matching, para evitar duplicar la formula de compatibilidad en el cliente.

Tambien se ajusto la presentacion visual del apartado Comunidad para que las
tarjetas no se distorsionen cuando hay nombres largos o porcentajes con
decimales.

## Objetivo

Cubrir los criterios de aceptacion del ticket:

1. Las tarjetas muestran el badge "% compatible".
2. Existe una pantalla de detalle de afinidad.
3. El porcentaje coincide con el backend.

## Contrato backend utilizado

El frontend consume el endpoint ya implementado en backend:

```text
GET /api/v1/matching/recomendaciones?page=1&limit=10
```

Respuesta esperada:

```ts
{
  page: number;
  limit: number;
  total: number;
  totalPages: number;
  recomendaciones: Array<{
    usuario: {
      id: number;
      nombre: string;
      apellido: string;
      usuario: string;
      ciudad: number;
      foto?: string;
      bio?: string;
      intereses: CatalogItem[];
    };
    compatibilidad: number;
    desglose: {
      ciudad: number;
      intereses: number;
      estiloVida: number;
      edad: number;
      laboral: number;
    };
  }>;
}
```

El campo `compatibilidad` se renderiza tal como llega del backend. El frontend
no recalcula el porcentaje.

## Ajuste visual del apartado Comunidad

Archivo:

```text
src/styles/layouts.css
```

Problema detectado:

Las tarjetas de Comunidad se veian comprimidas y distorsionadas en la barra
lateral porque avatar, nombre largo, usuario y badge competian por el mismo
espacio horizontal.

Solucion aplicada:

1. Se cambio la tarjeta de recomendacion a una grilla de dos columnas:
   avatar a la izquierda y contenido a la derecha.
2. El badge queda debajo del nombre/usuario dentro de la misma tarjeta.
3. Se aumento levemente el avatar para equilibrar la composicion.
4. Se elimino el desplazamiento horizontal en hover y se reemplazo por una
   elevacion sutil.
5. Se mantuvo el truncamiento con puntos suspensivos para nombres y usuarios
   largos.
