# HG-F3-032 - Configuración de despliegue en Railway

## Resumen

Se agrega `railway.json` para desplegar el frontend en Railway. Sustituye a
Render como plataforma elegida; el contexto completo está en
`higirlbackend/Docs/TICKET-025.md`.

## Objetivo

Alojar el frontend en la única plataforma cuya cuenta está funcionando: Vercel
bloqueó el registro por verificación telefónica y la cuenta de Render sigue sin
confirmarse.

## Alcance Implementado

```json
{
  "build":  { "buildCommand": "npm ci && npm run build" },
  "deploy": { "startCommand": "npm start -- -H 0.0.0.0 -p $PORT" }
}
```

`-H 0.0.0.0` y `-p $PORT` explícitos por la misma razón que en el backend: el
enrutador llega desde fuera del contenedor y no alcanzaría un socket atado al
loopback.

## El problema que Railway resuelve solo

`NEXT_PUBLIC_API_URL` se incrusta en el bundle durante `next build`. En Render
eso obligaba a desplegar el backend, anotar su dominio, escribirlo a mano y
volver a desplegar el frontend.

Railway resuelve referencias entre servicios **también en tiempo de build**:

```text
NEXT_PUBLIC_API_URL = https://${{higirl-backend.RAILWAY_PUBLIC_DOMAIN}}/api/v1
```

Se resuelve sola en cada build. Sigue siendo cierto que **un cambio de dominio
del backend exige redesplegar el frontend**: la variable quedó dentro del
bundle, no se lee al arrancar.

`NEXT_PUBLIC_API_ORIGIN` no se declara: `infrastructure/config/env.ts` la deduce
quitándole el sufijo `/api/v1`.

## Archivos Modificados

```text
railway.json    NUEVO
```

`render.yaml` (HG-F3-031) se conserva como alternativa si el crédito de Railway
se agota antes de la presentación.

## Criterios de Aceptación

- [x] El frontend se despliega sin cuenta en Vercel ni en Render.
- [x] El comando de arranque escucha en `0.0.0.0` y en el `PORT` inyectado.
- [x] La URL del backend no se escribe a mano.
- [x] El build sigue pasando.

## Pruebas Realizadas

```powershell
npm.cmd run build
```

Resultado: build correcto, con `/chats` y `/verificar-email` como rutas
dinámicas.

`railway.json` se validó como JSON y sus campos se contrastaron con el esquema
oficial de Railway.

**No verificado:** el despliegue en sí.
