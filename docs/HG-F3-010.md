# HG-F3-010 - Validaciones de Registro de Usuario (HIGIRL-60)

## Resumen

Se implementaron todas las validaciones del formulario de registro según el
ticket HIGIRL-60: validación por campo inline (sin `alert()`), toggle de
visibilidad de contraseña, campo de fecha de nacimiento con restricción de
mayoría de edad, y selector de ciudad cargado dinámicamente desde el backend.

## Objetivo

Cubrir las siguientes reglas de validación en el cliente:

| Campo | Regla |
|---|---|
| Nombre / Apellido | Obligatorio, 2–50 chars, solo letras y espacios |
| Correo | Obligatorio, formato válido |
| Contraseña | ≥ 8 chars, 1 mayúscula, 1 minúscula, 1 número |
| Confirmar contraseña | Debe coincidir con contraseña |
| Fecha de nacimiento | Obligatoria, debe dar edad ≥ 18 años |
| Ciudad | Obligatoria, selección desde catálogo del backend |

Además: botón ojo (👁) en los campos de contraseña para revelar/ocultar texto.

## Fecha y rama

- Fecha de cierre: 2026-06-21
- Repositorio: `higirlfrontend`
- Rama: `feature/edu-2026-dev`
- Next.js: `16.2.7`
- TypeScript: `5`

## Problema anterior

- El formulario solo tenía 4 campos (nombre, apellido, email, contraseña/confirmar).
- La única validación en cliente era un `alert()` si las contraseñas no coincidían.
- No existían campos de ciudad ni fecha de nacimiento.
- No había toggle de visibilidad en los campos de contraseña.

## Nuevos archivos

### `src/features/auth/hooks/useRegisterValidation.ts`

Hook que centraliza todas las reglas de validación del formulario. Devuelve:

- `validateField(name, value, fields)` — valida un campo individual.
- `touchField(name)` — marca el campo como tocado (activa la visualización del error).
- `validateAll(fields)` — valida todos los campos y retorna `true` si el form es válido.
- `getFieldError(name)` — retorna el error de un campo solo si ya fue tocado.

Estrategia de validación:

```
- onChange: re-valida el campo si ya fue tocado (no muestra errores en campos vírgenes).
- onBlur: marca el campo como tocado y valida.
- onSubmit: valida todos y marca todos como tocados, mostrando todos los errores pendientes.
```

Reglas implementadas:

```ts
// Nombre / Apellido
const LETTERS_ONLY = /^[a-zA-ZáéíóúÁÉÍÓÚüÜñÑ\s]+$/;

// Contraseña
const HAS_UPPER = /[A-Z]/;
const HAS_LOWER = /[a-z]/;
const HAS_DIGIT = /\d/;

// Edad mínima
function validateFechaNacimiento(v: string): string {
  const nac = new Date(v);
  let edad = hoy.getFullYear() - nac.getFullYear();
  if (!yaCumplio) edad--;
  if (edad < 18) return 'Debes tener al menos 18 años';
  return '';
}
```

`maxDate` se calcula así:

```ts
const maxDate = (() => {
  const d = new Date();
  d.setFullYear(d.getFullYear() - 18);
  return d.toISOString().split("T")[0];
})();
```

#### Submit sin `alert()`

Se eliminó el `alert("Las contraseñas no coinciden.")`. La coincidencia de
contraseñas ahora es una regla más del hook `useRegisterValidation` y se
muestra inline bajo el campo "Confirmar contraseña".

```ts
// Antes
if (formData.password !== formData.confirmPassword) {
  alert("Las contraseñas no coinciden.");
  return;
}

// Después
const isValid = validateAll(formData);
if (!isValid) return;
```

## Criterios de aceptación

- [x] Nombre con número → error "Solo letras y espacios" inline, sin submit.
- [x] Email inválido → error de formato inline.
- [x] Contraseña sin mayúscula → error descriptivo inline.
- [x] Contraseñas que no coinciden → error inline (sin `alert()`).
- [x] Fecha de nacimiento que da < 18 años → error inline.
- [x] Ciudad no seleccionada → error inline.
- [x] Clic en ojo → la contraseña se muestra/oculta.
- [x] Submit con formulario vacío → todos los campos muestran su error.
- [x] Submit con datos válidos → redirige al paso de intereses (`/intereses?onboarding=1`).
- [x] Selector de ciudad se deshabilita mientras carga y muestra "Cargando…".
- [x] `npx tsc --noEmit` → 0 errores.
