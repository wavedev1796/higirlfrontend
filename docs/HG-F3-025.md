# HG-F3-025 - Fix: el campo para escribir desaparece en conversaciones largas

## Resumen

En la pantalla de chat, al acumularse mensajes en una conversación, el composer
(el campo "Escribe un mensaje..." junto al botón de enviar) desaparecía de la
pantalla y ya no había forma de responder. El problema no dependía del tiempo ni
del scroll: aparecía en cuanto los mensajes sumaban más alto que el panel.

## Objetivo

Que el composer permanezca fijo al pie de la conversación con cualquier cantidad
de mensajes.

## Causa raíz

`.conversation-panel` era un grid con cuatro filas fijas declaradas:

```css
grid-template-rows: auto auto minmax(0, 1fr) auto;
/*                  header  error  scroll        composer */
```

Pero el banner de error se renderiza de forma condicional en `ChatView.tsx`
(`{chat.error && (...)}`). En el caso normal —sin error— el panel tiene **tres**
hijos, no cuatro, así que el reparto de filas se corría una posición:

| Hijo | Fila que recibía | Consecuencia |
|------|------------------|--------------|
| `.conversation-header` | `auto` | correcto |
| `.message-scroll` | `auto` | **se dimensionaba al contenido, sin techo** |
| `.message-composer` | `minmax(0, 1fr)` | quedaba empujado fuera del panel |

Como `.chat-page` tiene altura fija y `overflow: hidden`, el composer desplazado
simplemente se recortaba. `.message-scroll { min-height: 0 }` no protegía: una
fila `auto` se dimensiona a su contenido, no al espacio disponible, así que a más
mensajes más alto el scroll y más lejos el composer.

Es decir: el bug estaba latente desde siempre y solo se manifestaba cuando la
conversación crecía lo suficiente.

## Alcance Implementado

- **`.conversation-panel` pasa de grid a flex column.** Con flex el reparto ya no
  depende de cuántos hijos haya: header, banner de error y composer se
  dimensionan a su contenido y el scroll absorbe el resto, con error o sin él.
  Queda un comentario en el CSS explicando por qué no debe volver a ser un grid
  de filas fijas.
- **`.message-scroll` recibe `flex: 1`**, para que sea el elemento que absorbe el
  espacio sobrante (conserva `min-height: 0` y `overflow-y: auto`).
- **`.conversation-empty` pasa de `grid-row: 1 / -1` + `align-self: center` a
  `margin: auto`.** `grid-row` es una propiedad de grid y dejaba de aplicar; con
  `margin: auto` el estado "Selecciona una conversación" sigue centrado.

No hubo cambios en TSX: el marcado ya era correcto.

## Archivos Modificados

```text
src/styles/layouts.css   (.conversation-panel, .message-scroll, .conversation-empty)
```

## Criterios de Aceptación

- [x] El composer permanece visible con cualquier cantidad de mensajes.
- [x] El composer permanece visible haya o no banner de error.
- [x] El scroll de mensajes sigue funcionando y se mantiene al fondo al abrir un chat.
- [x] El estado "Selecciona una conversación" sigue centrado en el panel.
- [x] El comportamiento se mantiene en el breakpoint móvil (700 px).

## Pruebas Realizadas

```powershell
npm.cmd run lint
npm.cmd run build
```

Resultado:

- ESLint sin errores ni advertencias.
- Build de Next.js generado correctamente (18 rutas).

Verificación adicional: se reprodujeron ambos layouts (grid anterior vs. flex
nuevo) lado a lado en el navegador con 40 mensajes y el mismo alto de panel. Con
el grid el composer quedaba recortado fuera del contenedor; con flex se mantiene
visible al pie.
