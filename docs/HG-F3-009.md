# HG-F3-009 - Corrección del flujo de onboarding

## Resumen

Se corrigio el flujo de primer ingreso para que, al crear una cuenta o iniciar
sesion por primera vez, la usuaria pase por la seleccion de intereses antes de
completar su perfil, y no al reves como ocurria antes.

## Objetivo

Establecer un orden de pasos claro y secuencial para el onboarding inicial:

1. Registro (o login con cuenta nueva) → intereses → completar perfil → feed.
2. Logins posteriores (cuenta con intereses ya guardados) → feed directamente.

## Fecha y rama

- Fecha de cierre: 2026-06-16
- Repositorio: `higirlfrontend`
- Rama: `feature/edu-2026-dev`
- Next.js: `16.2.7`
- TypeScript: `5`

## Problema anterior

El formulario de registro redirigía directamente a `/profile/edit?onboarding=1`,
saltándose por completo la selección de intereses. El formulario de login no
detectaba si era un primer ingreso y enviaba siempre al dashboard o al
`callbackUrl`.

## Flujo corregido

```
Registro / primer login
    │
    ▼
/intereses?onboarding=1   ← Paso 1 de 2
    │  (guardar ≥ 3 intereses)
    ▼
/profile/edit?onboarding=1  ← Paso 2 de 2
    │  (completar perfil)
    ▼
/feed

Logins posteriores (interestsCount > 0)
    │
    ▼
/feed  (o callbackUrl si existe)
```

## Señal de "primer ingreso"

El endpoint `POST /api/v1/auth/login` ya retorna el arreglo `intereses` del
usuario. Si su longitud es `0`, el frontend infiere que es un primer ingreso y
activa el flujo de onboarding. No se requirio ningun cambio en el backend.

## Implementacion

### RegisterForm

Archivo:

```text
src/features/auth/components/RegisterForm.tsx
```

Cambio: tras registrar y obtener el token automatico, la redireccion pasa de
`/profile/edit?onboarding=1` a `/intereses?onboarding=1`.

```ts
// Antes
router.replace(`${ROUTES.PROFILE_EDIT}?onboarding=1`);

// Despues
router.replace(`${ROUTES.INTERESTS}?onboarding=1`);
```

### LoginForm

Archivo:

```text
src/features/auth/components/LoginForm.tsx
```

Cambio: se lee `response.intereses` para calcular `interestsCount`. Si es `0`,
la usuaria va al onboarding; de lo contrario va al `callbackUrl` o al
dashboard.

```ts
const interestsCount = (response.intereses ?? []).length;

if (interestsCount === 0) {
  router.replace(`${ROUTES.INTERESTS}?onboarding=1`);
  return;
}

const callbackUrl = searchParams.get('callbackUrl');
router.replace(callbackUrl?.startsWith('/') ? callbackUrl : ROUTES.DASHBOARD);
```

### InterestsSelection

Archivo:

```text
src/features/profile/components/InterestsSelection.tsx
```

Cambio: se agrego `useSearchParams` para leer `?onboarding=1`. Al guardar los
intereses, si esta en modo onboarding redirige a `/profile/edit?onboarding=1`
en vez del dashboard.

```ts
const isOnboarding = searchParams.get('onboarding') === '1';

// En handleSave, tras guardar:
if (onSuccess) {
  onSuccess();
} else if (isOnboarding) {
  router.replace(`${ROUTES.PROFILE_EDIT}?onboarding=1`);
} else {
  router.replace(ROUTES.DASHBOARD);
}
```

### Pagina de intereses

Archivo:

```text
src/app/(dashboard)/intereses/page.tsx
```

Cambio: convertida a componente de cliente (`"use client"`). Cuando
`?onboarding=1` esta presente, muestra un banner de progreso **"Paso 1 de 2"**
identico al que usa la pagina de edicion de perfil.

### EditProfileForm

Archivo:

```text
src/features/profile/components/EditProfileForm.tsx
```

Cambios:

1. El banner de onboarding ahora dice **"Paso 2 de 2"** (antes decia
   "Paso final").
2. Al guardar el perfil en modo onboarding, la redireccion va a `ROUTES.DASHBOARD`
   en vez de `ROUTES.PROFILE`, cerrando el ciclo de onboarding.

```ts
// Antes
router.replace(ROUTES.PROFILE);

// Despues
router.replace(isOnboarding ? ROUTES.DASHBOARD : ROUTES.PROFILE);
```

## Criterios de aceptacion

- [x] El registro redirige a la seleccion de intereses como primer paso.
- [x] El login detecta usuarios sin intereses y los envia al onboarding.
- [x] Al guardar intereses en onboarding, se avanza a completar el perfil.
- [x] Al completar el perfil en onboarding, se llega al feed.
- [x] Logins posteriores (con intereses) van directo al feed.
- [x] La pagina de intereses muestra "Paso 1 de 2" durante el onboarding.
- [x] La pagina de edicion de perfil muestra "Paso 2 de 2" durante el onboarding.
- [x] El flujo de onboarding ocurre solo una vez (condicionado a tener 0 intereses).
